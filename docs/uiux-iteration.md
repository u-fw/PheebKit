# Material 3 workbench iteration

Owner objective: refactor UI/UX first, then complete the media workflows. This is an active implementation plan, not completed release evidence.

## Preserved contracts

Keep stable Wails v2, Go compiler/runner, local-only media, schema-1 projects, no-overwrite publication, explicit job admission, Undo/Redo, draft recovery and Chinese/English support. Adopt Material 3 and Material You design through the existing React UI; no Kotlin/Compose runtime migration. Glass is reserved for app chrome and floating elements; editing surfaces use tonal containers. No remote font, analytics or translation requests.

## Ordered deliverables

1. **Appearance and component foundation:** semantic Material color roles generated from a validated custom seed; preset palettes; system/light/dark mode; comfortable/compact density; persistence and old-theme compatibility; keyboard focus, contrast, reduced motion and forced-color fallback. Avoid layout-shifting press feedback.
2. **Workbench:** source preview and range editing stay central; inspector categories expose output, tracks, adjustments and advanced tools without a single long form. Keep state when switching categories. Preserve project/preset, sample, recovery and batch controls. Output checks and submit action stay easy to reach. Responsive layout works with English and enlarged text.
3. **Editing depth:** full-source preview, filmstrip and bounded waveform overview, selected-range loop, frame-step controls, accessible range editing and button/keyboard segment ordering. Never silently change output intent just by seeking or playing.
4. **Sample comparison:** synchronized original/output playback with explicit source time offset, seek/play/pause, visible compatibility fallback and split-frame comparison. Preserve raw paths and original media. Do not claim universal browser codec support or full-output quality from one sample.
5. **Batch recipes and preflight:** reusable bounded processing recipes, per-file planned operations/track choices/names and actionable errors before atomic queue admission. Recipes never start jobs on import/apply and do not silently reuse source-specific track indexes/ranges.
6. **Delivery:** update bilingual usage/screenshots and exact implementation limits; verify frontend checks, real media/core integration, actual native window and clean committed candidate packaging. Match installer provenance to source. Existing clean-client stable-release gates remain separate.

## Evidence required

- Pure tests for palette validation/contrast, preference migration, timing synchronization, range bounds and recipe/preflight invariants.
- Interaction QA for tab keyboard navigation, state retained across tab/theme/language changes, narrow layouts, both themes, reduced motion and readable focus states.
- Real original/output media playback or explicit codec fallback, source-offset seek, selected-range loop and bounded background thumbnail/waveform work.
- Existing processing, queue cancellation, project recovery and output protection must continue passing. No placeholder panels, invented metadata or decorative progress.

### Sample comparison implementation (in progress)

- A separately loaded comparison player synchronizes original time to sample time plus the recorded source offset. It seeks/pauses both players, stops at the shortest valid comparison duration and resynchronizes source drift beyond 80ms while playing. This is interactive browser playback, not a decoded-frame synchronization guarantee. Only one audio source is audible; original audio uses the player's default track. Buffer starvation pauses the comparison for an explicit retry. Unsupported playback switches to FFmpeg still frames with an explanation.
- Still comparison supports side-by-side images and a keyboard-accessible reveal slider. Preview images retain the 512px extraction bound and letterbox into a shared frame; crop/rotation can change geometric alignment. Only the latest seek starts after a pending extraction pair, avoiding a growing queue of stale frame work.
- Isolated browser evidence used the actual eight-second source and a real H.264/AAC sample encoded from 2.5–5.5 seconds. Initial times were 2.5/0, seek to sample 1 mapped to source 3.5, and playback offset was observed at about 2.5018 seconds. Both stopped at the sample end. Switching audio left exactly one player unmuted. Playback made zero frame requests. Frame mode requested source 3.5/sample 1; split reveal Home reached 0% without another extraction. Invalid video fixtures automatically switched to two still images. Rapid seeking with delayed frame responses kept at most two frame requests active and skipped superseded positions. The static fallback at 375px had no horizontal overflow; axe found zero violations/incomplete checks in that static state only.
- Source-preview ownership also handles late `play()` completion after the editor is hidden. An isolated delayed-play test hid the real video before releasing its play promise and confirmed it stayed paused without a false playback error.
- Preview URL reuse now preserves the existing capability for unchanged imported media. A regression reopens the same source 70 times and confirms its active URL remains valid; changed-source checks still reject stale content. Targeted app tests, including the real sample job/source-change comparison regression, pass. The newest frontend verification has 133 tests and includes nonzero comparison offsets/duration bounds. These browser adapters are test-only; actual native comparison IPC/playback remains to be exercised before release.

### Batch recipes and preflight — 2026-10-26

- Batch recipes reuse the existing bounded 20-preset store and schema-1 `.pheebpreset` format. Applying one explicitly changes the editable common parameters and resets per-file track overrides; it never submits work. Paths, ranges and source-specific indexes are excluded by the existing portable-settings policy. The recipe-management action opens the retained Tools panel and moves focus to its settings heading.
- Each selected file shows its output name, operation and known duration, independent track choices, compiler-selected encoder/reason, retained track indexes and expandable execution parameters. A sequential, cancellable preflight checks 1–32 files and collects individual failures. Stop finishes the current request before stopping further checks. Any relevant source, path, track or parameter change invalidates previous review; admission stays disabled until every current file passes. The existing atomic backend admission validates again, including no-overwrite protection; an admission failure clears the review and never claims partial success.
- Four added pure tests cover review-key invalidation, per-file frontend/backend failures, cancellation, immutable snapshots and the 32-file bound. The batch UI is separately loaded to keep the main production chunk below the bundler warning threshold. On sufficiently tall desktop windows the inspector stays visible beside long batch lists; narrower/shorter windows return it to the document flow.
- Isolated browser QA used actual Compress/BatchPanel components, an owned real source video and an explicitly synthetic IPC adapter. It exercised mixed pass/failure, all-pass without automatic submission, common-setting invalidation, stopping after the active request, recipe apply/reset, keyboard focus in recipe management, atomic-admission errors and an explicit two-project admission payload. A source track with index 3 retained index 3 rather than its display ordinal. Changing common parameters during a pending review discarded its result and skipped the next file. These checks establish frontend behavior, not native execution.
- At 375×812, English batch controls had no horizontal overflow. Axe 4.12.1 reported zero violations and two incomplete checks (obscured background contrast in the output dock and source-video captions); `.tools/batch-ui-20261026/axe-mobile.json` retains the local record.
