# Interface languages

PheebKit supports **Simplified Chinese (`zh-CN`) and English (`en-US`)**. Settings → Appearance → Interface language updates the interface immediately without remounting the editor, resetting parameters or starting work. The saved local preference is restored at launch; first launch follows the system/browser language (Chinese for `zh`, otherwise English). Windows using the same application origin receive preference changes through storage events.

Application labels, validation messages, statuses, dates, numeric display and accessibility labels are localized. Native dialog titles and filter descriptions use the selected language; system-owned buttons follow Windows display language. Each dialog awaits locale synchronization before opening. The backend accepts only the two supported codes.

User filenames, paths, preset names, metadata titles, command arguments, raw FFmpeg logs/help and third-party version/copyright text stay unchanged. Unknown tool errors remain visible verbatim. The shared dictionary translates known application messages, not arbitrary third-party output. If preference storage is unavailable, switching still works for the current session and Settings explains that it cannot persist.

## Maintaining translations

`locales/en.json` is the shared Chinese → English catalog, embedded by Go for native dialogs and imported by the frontend. Use `t("…{{0}}…", [value])` at display boundaries; keep state, semantic option values and saved project data language-neutral. Never pass user text through dictionary lookup. Mark user-owned select options `translate: false`. Preserve placeholder identities/counts while allowing English word order to differ.

Run `npm --prefix frontend test` for regressions and catalog source-coverage/placeholder/namespace guards. Follow with typecheck, lint, formatting and build. Native QA covers lazy Settings loading, switching both ways, retained editing state, restart persistence, dialog language and readable English layouts. Catalog coverage alone does not prove every display boundary calls the translator.

No online translation service or additional runtime dependency is used. README languages remain separate Markdown documents with reciprocal links.
