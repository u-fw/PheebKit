## Beta.5 reliability iteration — 2026-10-14

Every successful Windows FFmpeg operation now re-probes its temporary output before no-overwrite publication. The 30-second, cancellable check uses the existing bounded capture and local-file protocol policy. It checks readability, recognizable codecs, motion-video geometry, expected video/audio/subtitle counts and the requested compression codec. Failure/cancellation cleans the scratch directory and leaves the requested target absent. A destination created by another process remains protected by final no-overwrite publication.

The completed record stores observed track counts/duration and review warnings. Audio/video duration differences greater than `max(1 second, 2% of planned duration)` are visible warnings: container duration can include unselected tracks and codec delays. Unknown audio/video duration also warns; sparse subtitle-only files are exempt. This is metadata/structure verification, not a full decode scan, frame-quality assessment or guarantee that the duration matches intent. Existing history without evidence never gains a verification badge retroactively. The running UI stays at most 99% and identifies the final verification/save phase.

The queue adds Failed / Interrupted filtering. Failed, interrupted and cancelled records expose Adjust and Retry; this reuses the existing re-probe-and-edit flow, clears the old target and requires an explicit start to create a new task. Restored history never starts automatically, and saved argv is never executed.

Opening a `.ffproject` whose source no longer exists prompts a native file selection to relocate it. Cancellation leaves the current editor intact. The replacement is probed, source-specific intent is retained for review, and the output target is cleared (including when the chosen file was the former target). The original project is untouched. The restored editor is dirty until explicitly saved, so media replacement/exit retains existing unsaved-edit protection. Invalid trim/track/crop combinations remain subject to normal preview/compile validation. This is manual relocation, not automatic identity matching, crash recovery or autosave; recent-project navigation remains future work.

Evidence: real compiler → runner → FFmpeg → ffprobe → publication checks for compression, remux, WAV and SRT; missing-track, unavailable-probe, cancellation, unreadable-file and immutable-history regressions. A disposable browser fixture verified the failed filter, retry navigation, dirty-to-saved transition, 99% final phase and 375px light/dark layout without console errors. Fixture/server/tab were removed after verification. Native file-dialog click-through remains manual; the browser fixture does not establish native IPC behavior.

The beta.5 source checks passed with Go 1.27.2 and Node 24.19.0: `KOMPEG_INTEGRATION=1 go test ./...`, `go vet ./...`, 96 frontend tests in 17 files, TypeScript, ESLint and Prettier. Packaging additionally enforces dependency audits and a production Wails build. Native dialog selection, Windows 10/clean-machine smoke tests and signing remain publication checks; Android remains deferred.

The beta.4 workflow foundation below remains in place. Current batch/scheduling, tracks, remux/extraction, transforms, sample comparison and project/preset sharing are documented in [media tools](media-tools.md). Presets now exclude selected track indexes and crop margins in addition to trim/paths, while retaining generic all/none track policies.

Beta.2 (2026-10-12) separates time editing from list selection. Clicking hours/minutes/seconds selects the digits for direct entry; valid integer input updates immediately without opening or confirming a list. Only the arrow opens candidates (keyboard also supports Alt+Down). Invalid/empty drafts do not change the time, show a local range hint and restore the last valid value on blur/Enter/Escape. Entering the final hour/minute bounds smaller units to the actual duration; milliseconds and existing start/end range checks remain. Browser fixtures verified direct `1`, sequential `09`, out-of-range refusal, blur recovery, arrow/keyboard choices and external updates. Full native IPC remains a manual check.

## Behavior

Beta.3 (2026-10-12) protects the focused single-file project when replacing media, opening/reusing another project or exiting. A change to paths or semantic settings marks the project dirty; only a successful `.ffproject` save clears that baseline. Navigation to queue/settings keeps the mounted editor and does not prompt. Replacement offers Continue Editing, Discard and Continue, or Save Project and Continue. Cancelled/failed saves never proceed. Native close requests include unsaved state as well as jobs/downloads, with monotonic revisions refusing older frontend state. Force-kill/OS shutdown are outside this interactive guarantee; batch-specific UI drafts and invalid transient numeric text are not project files.

The trim panel now shows retained/removed duration and start-zero/end-source/reset-range actions. Output displays the final filename and offers explicit numbering around existing files/directories and active queued paths; suggestions are not reservations, and compile/final publication continue to refuse overwrite. Choosing an output or submitting a single/batch job remembers its existing directory in `preferences.json`, preserving presets/defaults. Missing remembered directories fall back to the source folder. Project output paths take precedence over this preference.

Evidence: idle-dirty close/stale-update Go regression; real filesystem numbering and queued-path checks; preferences preservation; 94 frontend tests; App browser fixture (test-only bridge) verifies unchanged navigation, retained/removed time, save cancellation preserving source, successful save then replacement, remembered folder defaults and numbering dispatch. Native save dialogs/Alt+F4 click-through remain manual acceptance.

1. Native window closing and application quitting check active backend jobs and environment setup. Active work opens a styled modal with Return and Cancel Work and Exit. Esc returns to the workspace, restoring trigger focus. Confirmation cancels the service contexts and waits for the job engine to finish before quitting. Idle windows close directly. Force-kill and OS shutdown are not interactive confirmation flows.
2. Completed jobs offer Open File and Show in Folder through Windows file associations/Explorer. The backend accepts only a known completed job's supported video/audio/text-subtitle output, checks that the file still exists and never interpolates a shell command. Reuse Settings is available for terminal jobs retaining Project intent. It re-probes the original media and returns to the processing form with a distinct suggested output path; the user starts a new task after reviewing settings. Technical errors remain available behind a readable explanation.
3. Trimming provides original-video and selected-range playback, keyboard-accessible location seeking, current-position boundary buttons and asynchronous boundary frames. The imported source is exposed through an opaque session URL with GET/HEAD/range support. Changed sources and unknown tokens are refused. Playback depends on WebView2's codec/container support; errors switch to FFmpeg position frames without requiring source transcoding. Frames are bounded to 512px and 2MiB, share two worker slots and a 12-second timeout. Boundary extraction is debounced and stale replies are ignored. Navigating away pauses playback. Playback stopping uses browser time updates and is a locating aid, not frame-exact playback.
4. Local defaults and up to 20 named presets save operation, encoding, resolution, audio, generic track policies, rotation/flip, volume and advanced argv settings. Trim/source/output, selected track indexes and crop are excluded. Same-name local saves update; shared imports refuse duplicates. Presets can be applied/deleted/imported/exported. Persisted settings pass ordinary frontend/backend validation when used; unavailable GPU choices are not fabricated. History retains editable settings, paths, status and bounded logs, normally the newest 200 jobs. Live jobs from other processes are preserved even if that temporarily exceeds 200. Active records belonging to dead process IDs are shown as interrupted and never auto-executed. Reusing a task compiles new arguments from current media/capabilities.

## Storage

The pinned Wails Windows asset writer buffers each response. Video GET ranges are therefore capped to 2MiB per response, single ranges only; large unbounded GETs are refused and playback can fall back to position frames. Small sources may be served in full. HEAD responses do not read the body. Range limiting/overflow/suffix handling has dedicated regressions, and native WebView2's subsequent-range behavior remains part of the manual playback check.

`%APPDATA%/kompeg/preferences.json` and `history.json` use version 1 and retain compatibility with existing FFmpeg configuration. Updates hold an OS file lock across read/merge/write, write a temporary file, flush it and atomically replace the owned JSON file. Reads/writes have a 24MiB bound. Malformed/unknown-version files are preserved, with a visible error rather than silent resetting. Local history contains file paths and diagnostics; it is not uploaded. Uninstall keeps AppData.

History is persisted at state transitions, including queued/running/completed/failed/cancelled. Progress is live in memory; an interrupted record can therefore show only the last persisted transition's progress. PID liveness conservatively excludes another running process's tasks from the current instance; PID reuse can delay classification until that process exits. This is restartable task history, not process pause/resume.
