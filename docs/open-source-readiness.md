## Before publishing

1. The owner selected `GPL-3.0-only`; the full license is in the repository's `LICENSE` and the scope is recorded in the README. Lightweight editions discover or download FFmpeg into a private directory. Bundled editions use only the publisher-pinned Gyan 9.0.2 full build whose archive and executable hashes are checked during release packaging; FFmpeg's GPL v3 license, README, build metadata, exact source commit and hashes accompany every bundled artifact. See [Windows distribution](windows-distribution.md) and [download policy](ffmpeg-downloads.md).
2. The owner authorized and configured the public `u-fw/PheebKit` remote. Before each push/release, review author/contact metadata, machine-specific verification notes and the exact source revision; never publish private screenshots, paths, logs or credentials.
3. Windows CI provisions publisher-pinned FFmpeg and runs real media checks, builds/packages candidates and verifies installer lifecycle. Manual dispatch accepts a reviewed previous-version tag for isolated build/upgrade acceptance. The rc.5 package source revision `94665cb` passed [hosted run 40275376229](https://github.com/u-fw/PheebKit/actions/runs/40275376229) and [checks-only run 40275353795](https://github.com/u-fw/PheebKit/actions/runs/40275353795); its rc.5 assets and GitHub digests match the release `SHA256SUMS.txt`. GPU qualification still needs an appropriate test machine and cannot be inferred from a generic hosted CPU runner.
4. Keep the scope clear: the release shell is stable Wails v2.17.0, while Wails v3 Beta was approved only for the historical Technical Spike. Android is deferred and may later use native Jetpack Compose. APK/device execution, HDR encoding, signing, clean-machine installation and a multi-source timeline remain unverified or unimplemented. Native sample/batch workflows now have click-through evidence, but clean Windows and CPU-only machines still need separate acceptance. Local installer lifecycle checks are in [Windows distribution](windows-distribution.md).
5. Repository hardening snapshot (2026-10-28): private vulnerability reporting is enabled, versioned Dependabot schedules are declared for Go, npm and GitHub Actions, a read-only dependency audit runs on changes and weekly, and the release workflow creates isolated Sigstore-backed provenance for every packaged file before publication. The public API reports that `main` is not protected and the rc.5 Release is not marked immutable; rc.5 predates these hardening changes and artifact attestations. Before stable publication, the owner should enable a main-branch ruleset with required checks and GitHub's immutable-release setting, then verify Dependabot alerts/security updates in repository settings.

An Android shared-package cross-build verifies source portability only. The full cross-platform acceptance criteria remain open until an APK launches on a device or emulator and proves the Go bridge.
