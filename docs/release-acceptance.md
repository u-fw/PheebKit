## Repeatable local checks

1. Use a clean committed checkout, Go 1.27.3+, Node 24+, the pinned Wails CLI and verified Inno compiler. Update `VERSION`, run `node scripts/sync-version.mjs`, write matching `RELEASE_NOTES.md`, then commit.
2. Build frontend assets before loading the root Go package: `npm --prefix frontend ci`, then `npm --prefix frontend run build`. The release script now performs this bootstrap itself. Source text checkout rules keep JS/HTML compatible with formatting checks on Windows.
3. Run `scripts/setup-test-ffmpeg.ps1` once into a fresh `.tools` destination. It verifies the publisher-pinned Gyan archive and extracted binary hashes, sets process-local `PHEEBKIT_FFMPEG`/`PHEEBKIT_FFPROBE`, and supplies the same paths to subsequent GitHub steps. No system PATH or application configuration is changed. Existing manifests are refused; this is not an unverified cache.
4. Set `PHEEBKIT_INTEGRATION=1`; use `$packages = @(& ./scripts/project-go-packages.ps1)`, then run `go test @packages -count=1`, `go vet @packages` and pinned `staticcheck@v0.8.2`. Run frontend tests, typecheck, lint, formatting and version tests. The package helper excludes third-party Go files found under the frontend dependency directory. The process-interruption test kills only its own headless test child; it proves checkpoint persistence and recovery without automatic task execution.
5. Run `scripts/release-windows.ps1`. It refuses dirty sources/existing version directories, audits dependencies, performs lightweight and bundled production builds and creates the two direct EXEs, sidecar-runtime portable ZIP, bundled installer and SHA-256 manifest. The script verifies the embedded payload digest/version, runs binary vulnerability checks on both EXEs, and packages project license, mode-specific notices, release notes and `BUILD_INFO.json`. Query each EXE with `--build-info`; run bundled variants with `--environment-info` in an isolated APPDATA/LOCALAPPDATA/PATH environment to prove `source: bundled`, exact 9.0.2 execution and reuse on a second launch. Wails v2 disables automatic Go VCS stamping; linker-stamped provenance is checked through the executable's query.
6. For version updates, build a reviewed existing local tag: `scripts/prepare-upgrade-baseline.ps1 -Ref v0.2.0-beta.7`. It creates an isolated detached worktree, builds the original source and removes the clean worktree. It does not fetch or modify tags. Execute `scripts/verify-windows-release.ps1 -PreviousReleaseDirectory (Get-Content .tools/upgrade-baseline-path.txt -Raw).Trim()`. An existing immutable local package from the verified matching source tag can instead be supplied directly with `-PreviousReleaseDirectory`.

Installer verification checks archive digests, both EXE identities, sidecar and embedded runtime execution, exact installer payload equality, actual older-version install → current upgrade, registration/version, running-application mutex refusal, reinstall, uninstall, and preservation of user-owned files and all four existing AppData JSON files. It refuses an existing registered real installation, uses workspace-owned directories and never opens the application window.

Before broadly distributing binaries, record the machine/OS/build and pass/fail evidence for these steps:

- Fresh Windows 10 and Windows 11 x64, normal user permissions, both existing and missing WebView2. Check explanatory missing-runtime wizard flow; no silent runtime installation.
- Launch from the installed directory and extracted ZIP. Test native media/open/save dialogs, Unicode/long paths, a read-only output directory, existing output refusal, and missing source relocation.
- Test no-FFmpeg setup/download cancellation and retry, a real CPU-only machine, and an actual qualified GPU. Check visible fallback and cancellation; hosted CPU checks do not qualify a GPU.
- Edit → checkpoint → close/forced termination → restart → explicit restore; verify the retained settings, no automatic execution, and an explicit output operation. The automated headless test is not native renderer/IPC or OS-shutdown coverage.
- Settings → diagnostic preview → save/cancel/expired preview. Compare saved bytes with preview and review attachments before sharing.
- Run the repository's hosted Windows workflow. Ordinary PR/main and checks-only runs verify source and a production binary without packaging. Prerelease-tag or manual packaging runs also verify installer lifecycle. For an update, dispatch packaging with a reviewed previous tag; cross-version acceptance remains optional and must be requested for that update candidate. A final-tag push verifies only; final packaging/publication requires a manual matching `release_tag` and reviewed exact-revision `stable_evidence`.
- Choose public repository identity/contact, configure private security reporting, review public history/assets and matching corresponding source, and decide signing. Keep unsigned/Beta status visible. An accessible local tag is not a public source release.

No hosted CI, clean-machine, signing or native-dialog result is inferred from local builds. Never replace already published assets for the same version; publish a new version for changes.
