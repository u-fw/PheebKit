# PheebKit 0.2.0 stabilization

The release scope is Windows 10/11 x64 local media processing. Freeze new feature work while closing the acceptance matrix. Android, network/capture, HDR, arbitrary multi-source timelines and unrestricted FFmpeg authoring are outside this release. Missing future features do not become silent stable-release promises.

The 2026-10-26 rc.4 packaging scan detected [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) in Go 1.27.2 through the FFmpeg download path. The build stopped before publishing artifacts. The source now pins stable Go 1.27.3, with the release minimum and hosted CI updated together. Earlier Go-version records below are dated evidence; new binaries require the patched toolchain and fresh source/binary audits.

The same dependency audit pass resolved [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) by advancing the lockfile's transitive `zod` package used by `eslint-plugin-react-hooks` to 4.6.7. It is a development-only tool, but the lockfile remains fail-closed because CI runs `npm audit --audit-level=low`. A clean Node 24 reinstall, full frontend suite and audit passed after the refresh.

On 2026-10-18 the owner explicitly chose migration from Wails v3 Beta to stable Wails v2.17.0. Go and npm v3 runtimes are removed. The existing Go media engine, React interface, schema-1 files, AppData paths and installer identity are retained. The native adapter supplies typed dialogs/events/quit; the renderer binds only the reviewed `DesktopAPI` (**61** methods in the current worktree, including bounded source-waveform extraction and the validated Windows system-accent read). Generated TypeScript interfaces describe JSON timestamps as strings and nullable pointers/slices without weakening strict checks. The active [Material workbench iteration](uiux-iteration.md) records development evidence separately from release acceptance.

The local target is `0.2.0-rc.5`, the Material-workbench and bundled-distribution verification candidate for `0.2.0`. The [iteration record](uiux-iteration.md) documents the current dynamic-color, command-palette, adaptive-shell, native sample/batch workflows and remaining package/CI checks. RC does not claim production acceptance. Final-version packaging is fail-closed: `scripts/release-windows.ps1 -StableEvidence <reviewed-file.json>` requires records for all checks below, matching the exact `VERSION` and clean Git revision. There is no force/skip-stability switch. Passing an attestation validator validates its shape and revision, not the truth of external reports; maintainers must inspect actual evidence.

Evidence JSON has `schemaVersion: 1`, `version`, `sourceRevision` and `checks`. Each named check must contain `passed: true`, a meaningful `evidence` reference, `verifiedBy` and `verifiedOn` (YYYY-MM-DD). Do not fill unperformed checks with success. Keep private screenshots, source paths, logs and diagnostic attachments out of public records. A final-version workflow dispatch accepts the reviewed JSON via its `stable_evidence` input; candidate packages need no stable attestation and stay explicitly prerelease.

Signing is a separate owner decision, not an automatic mark of functional stability. Candidate assets are unsigned. The owner subsequently authorized public repository creation and source push to [u-fw/PheebKit](https://github.com/u-fw/PheebKit); private vulnerability reporting is enabled. Stable binary publication still requires the acceptance records above.

## Local evidence — 2026-10-18

The stable Wails build boots on the current Windows 11 Pro build 26300 workstation. Native multi-file dialog opens/cancels and imports a generated `测试 & clip.mp4`; the real renderer → Desktop IPC → service → qualified RTX 4070 NVENC workflow completes an eight-second HEVC/AAC job. The queue receives progress/completion and postflight structure verification. An independent FFmpeg full decode succeeds with duration 8.000 seconds. Native maximise/restore synchronizes the custom titlebar state. These observations do not establish clean-machine, Windows 10 or CPU-only compatibility.

The migration passed 120 frontend tests and the uncached local Go media integration suite at that dated point. The current Material You, readiness and native-feedback source passes **151 frontend tests in 32 files**, **1,410 translation entries**, strict TypeScript/ESLint/Prettier and the production frontend build; Go integration, vet and source `govulncheck` also pass against the verified local FFmpeg pair. Dedicated regressions cover the current 61-method renderer boundary, missing remembered dialog directories, direct Wails v2 event payloads, drop listener cleanup, system-accent conversion, notification text sanitization and rejection of absent/failed/stale stable evidence. Final gate/package and further native results are recorded in the release acceptance and distribution documents when performed.

The exact clean source `8f296f77e555469d3bdc6b9820441c3ad09568b5` passed the hosted Windows workflow [40259965174](https://github.com/u-fw/PheebKit/actions/runs/40259965174) in 4m33s. That run executed the publisher-pinned real FFmpeg/process-interruption suite, Wails production packaging, isolated installer lifecycle checks and uploaded `PheebKit-windows-x64` artifact `12624327737` with archive digest `sha256:af35a6d5a3b5f2c80e0daa3208dae5cf28634c67a41bddbc4e5154554cf5882a`. The clean local production binary reports revision `8f296f7`, `modified=false`, and SHA-256 `E39467E2F4E3790FDD638F4C090543950F1D60532FFE101081E07EA32FF719D7`. This closes the exact-revision hosted-CI gate; clean Windows 10/11, CPU-only, signing and current-installer native click-through remain separate decisions or gates.

The first hosted run, [39101680862](https://github.com/u-fw/PheebKit/actions/runs/39101680862), exposed three PATH-dependent integration tests and a same-size source edit missed with coarse filesystem change times. The rc.2 fixes provision the PATH tests from the verified tools without modifying system PATH, and fully hash sources up to 4 MiB. Larger sources retain bounded sampling and its documented limits. The candidate also adds a side-effect-free `PheebKit.exe --build-info` query; local production execution confirms the actual linked version, revision, modified status and framework. Packaging and installer checks compare this response with the payload manifest. rc.1 is retained as a superseded local artifact.

Final binary auditing additionally found five known HTTP/2 advisories in the Wails production-tag dependency graph (`golang.org/x/net v0.56.0`), which ordinary untagged source analysis did not cover. The minimum official fixed version is v0.60.0; its verified module requirements raise the Go language baseline to 1.26 and update the related x/crypto, x/sys and x/text dependencies. Release builds now require the patched Go 1.27.3+ baseline. Both packaging and checks-only CI audit the actual built EXE. The unpublished pre-fix rc.2 package is archived outside release outputs; no vulnerable binary is published as a release.

The following hosted run reached real-media tests and isolated a copied-tool startup failure in the shared-configuration case. Validation now preserves context cancellation/deadline causes and includes bounded stderr, rather than hiding the reason behind an exit code. The finite environment validation budget is 30 seconds for cold launches. Focused real shared-configuration regressions pass locally. User-visible legacy brand messages are corrected while compatibility identifiers remain unchanged. The [README screenshots](images/README.md) show the actual Windows application and self-generated test media; rc.3 adds the actual [runtime language selector](i18n.md).
