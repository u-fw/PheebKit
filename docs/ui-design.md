# Shared UI design

## Active Material workbench iteration (2026-10-26)

The current source keeps stable Wails v2 and React and implements Jetpack Compose, Material 3 and Material You design principles without introducing a second desktop runtime. The official Material Color Utilities generate HCT palettes from a validated seed. Settings exposes system/light/dark mode, preset/custom palettes, a Windows Material You seed and comfortable/compact density. The Windows accent is read through the reviewed `GetSystemAccent` desktop boundary and refreshed when the window regains focus; this is a Windows system-color integration, not a wallpaper-content extractor.

The shared control layer adds pointer ripples, restrained panel/page transitions, reduced-motion handling, visible focus and 44px compact controls. `Ctrl+K` opens a searchable command palette with localized labels, arrow/Home/End/Enter navigation, disabled-action handling and trigger-focus restoration. Reversible queue schedule changes use an inverse-color snackbar with hover/focus-aware expiry and Undo. Tonal surfaces carry editor hierarchy; translucent glass remains limited to navigation, app bar, command overlay and floating output controls. This section supersedes the fixed palette/opacity/layout values in the earlier spike record below. Future product directions and release-independent ideas are in the [design and feature roadmap](design-roadmap.md).

The processing workbench places source preview and ranges in the main editing column and retains four inspector panels (output, tracks, adjustments and tools). Keyboard arrow/Home/End navigation follows tab semantics; switching categories does not discard field state. A measured bottom dock keeps validation and submit reachable, with an expandable explanation/details panel and Escape/outside dismissal. The home import action precedes draft history, the three-step guide is collapsed, and appearance is the first Settings section.

The preview offers selected-range looping, nominal average-rate frame steps, explicitly loaded source filmstrip thumbnails and bounded mono waveform windows. These operations seek the source without changing output ranges. See [iteration status and exact verification limits](uiux-iteration.md); a development build is not release acceptance. The existing editor/compiler/queue and no-overwrite contracts remain unchanged.

## Earlier spike design record

The technical spike implements Home, Media Processing, Queue and Settings. Processing includes compression, remux, audio/text-subtitle extraction, basic transforms, batch controls, project/preset files and samples. The UI uses shared React components, TypeScript models generated from Go and a small binding adapter. Behavior is documented in [workflows](workflows.md) and [media tools](media-tools.md).

Material Design 3 inspired tonal surfaces, teal accent and a consistent 4/8px spacing scale form the visual system. The supplied PheebKit artwork is shared by navigation and the favicon and converted to Windows icons; the Chinese brand is 菲比工具箱. A restrained mint/lilac canvas sits behind the glass navigation: sidebar opacity is 60% light / 62% dark, while chrome opacity is 80% light / 84% dark. Glass is limited to the sidebar, top app bar and mobile bottom navigation, with 26px backdrop blur and a subtle inset highlight. Cards use opaque tonal surfaces without repeated blur. All colors, spacing, radii, elevation and motion use semantic CSS tokens.

The desktop app bar is 56px, page gutters are 32px and page titles are 30px. Local system fonts keep startup offline. Navigation and body labels maintain clear type levels; redundant page eyebrows and mixed-language decoration have been removed. The desktop import panel uses a horizontal illustration/content composition; phones stack it vertically.

Filled primary buttons, pill navigation and checked segmented controls express selection and action hierarchy. Resolution, audio and preset use a shared Material combobox/listbox rather than an operating-system dropdown. Arrow keys, Home/End, typeahead, Enter, Escape, Tab and outside clicks are supported. The trigger retains focus while `aria-activedescendant` identifies the active option. Menus choose above/below placement and constrain height between the fixed top/bottom bars. Phone controls stack into one column; codec tiles and segmented groups adapt to enlarged text.

The vendor-prefixed backdrop declaration precedes the standard declaration. The previous reverse order caused production CSS optimization to retain only a WebKit property that the audited Chromium WebView did not recognize. Final native verification confirms the standard computed value is `blur(26px)`; transparency alone is not treated as blur proof.

`frontend/src/styles.css` is the stylesheet entrypoint. Tokens, base rules, shell, workspace, media, compression, select, execution, queue, settings and responsive rules live in separate files under `frontend/src/styles/`. Their declaration order is preserved; the split produces identical production assets.

Windows uses a frameless Wails window with an integrated glass app bar, native drag region and custom minimize/maximize/restore/close controls calling the Wails Window API. OS shadows and Windows 11 corner decorations remain enabled. Composition hosting is not enabled. Android/browser layouts do not show desktop window controls. The native title is `菲比工具箱 · PheebKit`. Native closing hooks protect active work; the styled modal uses dialog semantics, safe default focus and Esc/trigger-focus restoration. The current implementation uses stable Wails v2; see the local [stability record](stability.md).

Desktop uses a sidebar. Widths up to 960px switch to a bottom navigation rather than shrinking the desktop sidebar, including phone landscape. The content and scroll focus padding consume the bottom bar's measured height, so enlarged text cannot move navigation over reachable controls. Safe-area insets, 44+ px targets, focus outlines, semantic controls and reduced-motion settings support touch and keyboard use. Light and dark themes use local persistence; fonts use the local system stack so the application works offline.

Home begins with file selection or drag/drop. A real Go probe result supplies the Media Card; no example file is presented as an imported file. Compress exposes codec family, quality, resolution, audio and output. Advanced controls expose encoder-specific quality, preset and one argv element per raw-argument line. UI never constructs the executable command. Switching codec family resets a GPU-specific encoder choice to automatic preference, because that encoder may not encode the new family.

Execution parameter preview comes from the Go compiler. Raw parameters are appended to output options with protected input/output/process flags. Codec-private suboptions use a typed safe allowlist to prevent auxiliary file access. Preview is refreshed after a debounce. Loading and validation errors appear beside the start button. Size mode with copied audio has a source-aware inline explanation and an explicit switch-to-AAC action; audio selection is never silently changed. Decimal MB and binary MiB are labeled consistently.

Progress combines throttled Go events with a short UI batching interval. Queue entries are independent records with progress/FPS/speed/out_time, cancellation, bounded logs and actual result metrics. Pause/resume of the FFmpeg process is outside this spike; cancel is a real process cancellation operation.

Size mode is a one-pass bitrate budget with muxing allowance and is an estimate, not a hard byte-size guarantee. Quality mode shows content-dependent size rather than inventing a percentage forecast. New settings default to automatic GPU preference; the actual compiler-selected encoder and any CPU fallback reason are displayed in the summary. Settings lists detected adapters and separately reports each encoder's real runtime trial result. CPU can be selected explicitly.

Media artwork loads asynchronously after probe. Windows `IShellItemImageFactory` is preferred, using the system's thumbnail provider to approximate Explorer's result. If unavailable, FFmpeg extracts an attached picture or a video frame. Failures retain a clear placeholder without preventing compression. Artwork is bounded and local; arbitrary paths must first pass the normal media import/probe flow.

Settings shows FFmpeg/ffprobe's actual executable paths, detected versions and configuration sources. Explicit environment variables take priority over saved application paths and PATH discovery. Missing binaries show an actionable setup message in the workspace and can be selected from Settings. Path changes are rejected while jobs are queued or running.

Responsive browser verification demonstrates shared layout; it does not prove an Android APK or native binding works. See the verification report for actual observed evidence.
