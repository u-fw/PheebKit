# Security and performance audit — 2026-10-13, current status 2026-10-29

## rc.6 follow-up — 2026-10-29

- A focused Windows test reproduced a descendant surviving cancellation when it was created between `Start` and Job Object attachment. Children now start suspended, are attached before the primary thread resumes, and retain cancellation requested before attachment. Regressions cover the start window, early cancellation, normal exit and descendant termination. The implementation uses documented Toolhelp, GetThreadTimes and ResumeThread APIs; it does not depend on an undocumented process-resume syscall.
- Queue gap reconciliation formerly abandoned a failed IPC read until another gap arrived. It now coalesces concurrent requests and retries with 0.5–30-second backoff, stops after success, and disposes pending work on unmount. Tests cover an isolated last-event failure, retry bounds/reset, concurrent gaps and disposal.
- A final history write failure formerly ended shutdown without a user decision. The manager now returns the failure and supports a serialized retry after stopping. Native idle close flushes off the window thread; failed writes keep a modal with explicit retry or exit-without-history actions. Further native close attempts cannot bypass an incomplete flush or unacknowledged failure. Tests cover disk failures, recovery, explicit acknowledgement and nonblocking close; generated output media is never removed by this flow.
- Weekly security checks now build and audit the actual Wails production EXE in addition to source. The rc.5 published binary has not been replaced. Main push CI success must not be described as installer/package acceptance: those conditional jobs run only in a separate candidate or authorized release run.
- Hosted `-race` run [40880245849](https://github.com/u-fw/PheebKit/actions/runs/40880245849) exposed local writer contention: 16 goroutines consumed the same three-second OS-lock budget, so some updates timed out. A reference-counted per-path process mutex now queues same-process writes before the unchanged cross-process timeout begins. Idle entries are removed; different files remain independent. Regression holds a writer beyond that timeout and verifies both updates, independent-file progress and registry cleanup. The fix does not increase timeouts or disable race checks.

Beta.11 adds opt-in typed audio filters with finite/range checks, eight EQ bands/four selected audio tracks, encoder-compatible rates and enum-only channel conversion. No user filter expression/path enters the graph. Missing filters, unknown duration for fades, overlapping fades and Copy/muted/no-track processing are refused before admission. Explicit sample-format/resampling adapters preserve strict video-depth behavior without weakening checks; output rate/requested channels are verified before publication. Deep clones cover settings/presets/batch/queue state; original full-output fade intent is validated before samples omit those envelopes. [Audio evidence](audio-processing.md) records actual measured behavior and limitations.

Beta.9 (2026-10-15) adds conservative local decode recovery. The current scan uses a 30-second coarse pass and subdivides only failed ranges; one cancellable scan per instance, finite integer 1–30-second windows, a six-hour source bound, two-minute per-probe and twelve-hour overall deadlines, bounded process output and one decoder thread. At most 720 coarse checks and 4,320 fine windows may run, with an absolute 5,040-probe ceiling; excess fine windows are rejected before decoding. Unknown operational errors abort rather than classify content for deletion. Scans participate in close/configuration guards without holding lifecycle locks across configuration waits. Recovery graphs retain the 16-piece/four-audio-track bounds, accept typed ranges only and cannot use raw options. Complete output decode has a twelve-hour deadline and must succeed before publication. Regression evidence and detection limits are in [media recovery](media-recovery.md); these are resource limits, not an OS memory sandbox.

Scope: native Windows 11 x64, PowerShell 7, PheebKit Windows release candidate. Reviewed compiler argv, runner process/output boundaries, media assets/cache, download/archives, project/preset persistence, queue events/history, frontend edit state and pinned dependencies. Findings below are confirmed and remediated locally; publication remains separate from functional security conclusions.

Current dependency note (2026-10-28): the Windows release candidate uses stable Wails v2.17.0 and Go 1.27.3+. The Node 24 frontend lockfile resolves the transitive ESLint-Hooks `zod` package to 4.6.7 for GHSA-mrhx-c7xc-m3w5. Final-binary auditing found GO-2026-6866 and GO-2026-6860 in the Wails dependency graph's `golang.org/x/net` v0.60.0; the module is now v0.62.0, with compatible x/crypto v0.58.0 and x/text v0.43.0 updates. `npm audit --audit-level=low`, `npm ci`, frontend tests/typecheck/lint/format/build, source `govulncheck` and final-binary `govulncheck` pass. The zod package is development-only and does not enter the desktop bundle.

Beta.8 (2026-10-15) extends those boundaries: fixed-category/name-checked FFmpeg inspection with 10-second operation deadlines including lock waits, 4 MiB accepted query output, binary-identity cache invalidation and 50-row GUI pages; same-source concat limited to 16 input seeks/four audio tracks and bounded decoding/filter concurrency; subtitle preparation uses forced external text formats/file-only input, bounded capture, a 16 MiB accepted ASS limit and source fingerprints. Generated fixed-name ASS is read from private scratch; user paths/fonts never become arbitrary filter expressions. These limits are not an OS process/memory sandbox or a general FFmpeg security audit. [Expansion evidence and unverified cases](ffmpeg-expansion.md) records actual tests.

## Verification and maintenance

Current source verification uses the project-scoped package list from `scripts/project-go-packages.ps1`, `go vet`, pinned `staticcheck@v0.8.2`, pinned `govulncheck@v1.9.0`, 166 frontend tests in 36 files, 1,424 translation entries, typecheck/lint/format/build and real FFmpeg integration for compiler, app and Windows runner. `npm audit --audit-level=low` reports zero advisories. Release packaging repeats these checks with Go 1.27.3+ / Node 24 and retains installer/ZIP checksums. A separate least-privilege job creates GitHub/Sigstore build provenance for every release file before publication; installer lifecycle acceptance is run separately.

Versioned Dependabot schedules cover Go, npm and GitHub Actions. `.github/workflows/security.yml` runs lockfile installation with scripts disabled, npm audit, pinned reachable Go vulnerability analysis, workflow linting and regression checks on dependency/workflow changes, weekly, and manually, all with read-only repository permissions. Repository-level alerts, mandatory branch protection, immutable releases and required status checks remain owner-controlled settings; the dated public API snapshot and recommended pre-stable actions are in [open-source readiness](open-source-readiness.md).

Compatibility closure: the first 128 MiB 7z ceiling refused the real publisher archive (LZMA2 property 31 = 192 MiB). It was corrected to a bounded 256 MiB ceiling, reducing the actual dictionary for smaller streams. Replaying the exact SHA-256-verified Gyan 9.0.2 full archive passed (56.41s), and the complete real download → hash → extract → AMD64/version validation → private configuration → capability scan/restart integration then passed (75.89s). The refused intermediate candidate was archived outside release outputs and is not the final build.

The release script and existing Windows CI now fail on vulnerability-check errors, rather than silently bypassing unavailable advisory services. No new production dependency, framework migration or Wails Beta upgrade was introduced. Existing Wails v3.0.0-beta.27 approval remains Technical Spike only. Old release artifacts remain historical and were not rebuilt with the patched SDK.

Hosted Windows CI executes the project-scoped Go suite with `go test -race` and `CGO_ENABLED=1`; the current source revision passes that job. The local workstation has no GCC/CGO toolchain configured, so its ordinary concurrency regressions are not local race-detector evidence. Native dialog/Alt+F4 IPC, Windows 10/11 clean-machine behavior, other GPU vendors and Android remain outside this run's verified coverage. Total decoder-process resource isolation remains a possible future improvement; current limits should not be described as a sandbox.

The CSP-hardened production EXE was also launched on the current Windows 11 host. Its document loaded, Wails IPC populated the real FFmpeg 9.0.2 status and the host's tested NVIDIA NVENC capability, and the window exited normally. This is a same-host smoke test for policy/runtime compatibility, not clean-machine or additional-GPU acceptance.
